# Claude CLI Sessions

`src/adapters/claude-cli/adapter.ts` selects persistent sessions when the request has its own conversation identity and retains isolated one-shot compatibility otherwise. Both paths use the operator's Claude Code sign-in, preserve subscription admission, refuse direct image input, and leave tool approval and execution with the external client.

## Persistent sessions

`src/adapters/claude-cli/session-context.ts` accepts an explicit Codex own-thread ID or a `thread-id`, `session_id`, or `session-id` header. Missing or invalid identity selects one-shot compatibility; a parent thread or prompt-cache cohort never supplies ownership. The SHA-256 scope binds the proxy home, durable client principal, provider/destination, and compaction versus conversation purpose. Model, Claude profile and account changes replace the worker without discarding outstanding receipts. Raw thread and account identifiers are not journal keys or log fields.

`src/server/auth-cors.ts` derives `durableClientPrincipalId` from an already-admitted credential, independently of process-local replay identities. Credentialless loopback has a stable local-operator namespace; an unrelated upstream bearer cannot change it. Responses, Chat, Messages, combo, compaction and WebSocket paths preserve the original trusted namespace before filtering local credentials. An explicitly unproven owner disables persistence; this namespace never grants admission.

`src/adapters/claude-cli/session-manager.ts` owns one live worker per scope. Workers use the OpenCodex home as a stable cwd and persist native CLI sessions. Each conversation has its own crypto-random native session ID, committed before dispatch; native metadata binds that ID to the directory and a hash of the binary, Claude profile and account identity. Fresh launches pass `sessionId`; verified continuations pass `resume` instead, always with `persistSession: true`. The worker API defaults persistence to false for compatibility with other callers.

`src/adapters/claude-cli/session-context.ts` compares normalized source-history prefixes and projects only the suffix the selected native session has not seen. This imports missing GPT, Gemini or other foreign turns as history without resending the retained prefix; a single new user message is sent as literal text. A fresh session projects the full latest client history, subject to the existing history cap. A compatible follow-up during active generation uses the SDK's native interrupt and drains the old generation through its terminal result before continuing on the same worker. The interrupt control acknowledgement alone does not establish that the generation has drained. Tool-catalog changes update the isolated MCP catalog without inserting a synthetic user turn.

During active generation or pending MCP work, live continuation accepts only known native assistant fragments, user instructions and known tool results; foreign assistant turns instead fall back to safe native planning and history catch-up so they are preserved.

`src/adapters/claude-cli/session-instructions.ts` restores queued instructions only against proven history boundaries. While external tool results are outstanding, follow-up user instructions enter a durable queue in acceptance order. Queuing preserves the pending MCP requests, supplies no synthetic tool result, and starts no inference. Once actual results are committed, queued instructions are folded into the context before the next inference; instructions already present in matching client history are not inserted twice.

`src/adapters/claude-cli/session-worker.ts` uses the official Agent SDK/native CLI pair `0.3.314` / `2.1.314`. Persistent mode requires a native executable: a Windows `.cmd` or `.bat` dispatcher fails with `cli_native_binary_required`. The worker disables built-in tools, setting sources, and all other MCP servers (`tools: []`, `settingSources: []`, `strictMcpConfig: true`). Its only MCP server is `opencodex`. The caller's folded system/developer prompt replaces the preset through the SDK initialize message on stdin; the spawn hook refuses a system-prompt argument in argv.

The production adapter supplies an allowlisted `options.env` without inherited `ANTHROPIC_*` variables or API credentials. SDK `0.3.314` copies that explicit environment rather than merging the host environment, then prepares its launch metadata; it does not restore host `ANTHROPIC_*` values or the host OAuth token. The custom spawn honors `launch.env`, `launch.signal` and cwd, strips the nested-CLI marker, and preserves the bridge's long MCP wait and disabled auto-background policies. The SDK supplies its own entrypoint, version and session-state defaults. Owned stderr is drained and discarded; process, input, stderr and arbitrary SDK failures expose generic errors rather than private diagnostics.

`src/adapters/claude-cli/session-events.ts` maps typed `SDKMessage` frames for persistent workers, including partial/final block correlation, tool identity and bounded arguments, usage and terminal errors. Persistent messages retain their SDK types through the worker and manager. One-shot Claude, CodeBuddy and Qoder retain the shared `src/adapters/coding-agent/protocol.ts` mapper and runner.

## External tool handoff

The persistent MCP handler requires the exact `claudecode/toolUseId` metadata, a current catalog name, and object arguments. The manager matches that ID, namespaced name, and canonical arguments against the completed assistant tool block before exposing a call. Only MCP calls that actually started are handed off; native sequential dispatch can receive the first real result before starting the next call, without waiting for every generated call to start. Tools receive no blanket concurrency annotation. Reusing an ID with different arguments fails closed. Each MCP request remains pending until Codex or another external client returns its actual result; the bridge neither approves nor executes tools and supplies no synthetic success result.

`src/adapters/claude-cli/session-journal.ts` commits receipts and accepted user instructions to the private `claude-cli-sessions.sqlite` under the OpenCodex home. Optional native metadata records the session ID, stable directory, identity hash, source-history hashes, completed assistant checkpoints and dirty bit within the existing version-1 snapshot; older records without it remain readable and start a fresh native session. SQLite WAL transactions use `synchronous=FULL`; directory, database, and sidecar permissions use the existing home guard and required ACL hardening. Version, shape, hash fields, and the 16 MiB UTF-8 record limit are validated on reads and writes. Corruption and database failures throw instead of becoming an empty history. Private records include tool arguments, outputs, queued instruction text and native transcript references.

The matched handoff and then `deliveryStarted: true` are committed before any external tool call is exposed. A durably captured handoff can be delivered on reconnect only if delivery never started. Issued calls are never automatically reissued, even after restart or a change to model, options, or tool catalog for the same logical history. Deduplication uses exact call IDs and operation receipts, never tool name plus arguments alone. A fresh call ID can represent a legitimate repeated user action with identical arguments.

Recorded results remain immutable in the journal. Outstanding results reject competing content or error bits, including a placeholder alongside an actual result; placeholder wording alone proves nothing about execution. For a completed receipt with a saved result, later historical output is normalized to that authoritative saved content and error bit, including shortened text or placeholder/real-output duplicates. This changes replay history, not the receipt. Historical call IDs still bind the original name, namespace, and canonical arguments; changed identities fail closed.

Incoming results are staged in a detached snapshot and committed before in-memory adoption or continuation. A saved result omitted from client history is restored beside its unique matching original assistant call, preserving tool namespaces, content and the error bit, including after an admitted continuation crashes. Receipts retain the pre-restoration input fingerprint so identical reconnects keep the restored generation. Retention prunes detached state, commits before adoption, and pins results until MCP completion. Missing or ambiguous origins needed for restoration, conflicting identities or outstanding results, and failed commits fail closed; uncommitted results cannot authorize continuation.

| Manager error | Status | Recovery |
| --- | --- | --- |
| `claude_tool_delivery_uncertain` | 409 | Verify whether the external action ran and return its original results; do not reissue the batch. |
| `claude_tool_results_pending` | 409 | Return every outstanding result under its existing call ID; queued user instructions do not settle tool execution. |
| `claude_tool_result_conflict` | 409 | Resolve competing outstanding results while preserving any committed content and error bit; completed historical outputs use the saved result. |
| `claude_recovery_history_missing` | 409 | Supply the unambiguous original assistant call so its saved result can be restored. |
| `claude_journal_write_failed` | 503 | Tool exposure is refused when its receipt or delivery marker cannot be committed. |

External execution can happen before a connection fails. There is no exactly-once delivery or execution guarantee: an issued host action with an unknown result requires verification and its original result, and cannot be automatically replayed. Session errors preserve status, code, retryability and available usage/error-type metadata.

## Reconnect and recovery

An HTTP disconnect leaves the existing generation available for the same active input to reconnect for 30 seconds. A different compatible follow-up uses the same-worker interrupt/drain or pending-tool instruction queue described above; a history rebase or configuration change replaces the worker through native history planning. Outstanding issued actions still require their actual results before inference continues. Idle workers stop after 30 minutes; the manager allows at most 16 live workers, evicting an idle one or returning `claude_worker_capacity` (503) when all are busy.

The manager detaches a stopped worker and invalidates its callbacks immediately. The real worker's concurrent/idempotent `stop()` returns one promise and rejects pending writes immediately. Once stopping starts, both successful and failed MCP handler settlements wait for that closing promise, preventing detached manager rejections, late external results or cancellation from reaching the CLI as tool results during shutdown. The manager still rejects and clears its detached pending promises; it does not abandon them. SDK output keeps draining without reaching parent callbacks.

With active MCP calls, shutdown first requests a native interrupt and waits at most one second for its control acknowledgement. It then closes the SDK/input stream before aborting MCP waits and closing the isolated server. This ordering prevents an interrupted-tool placeholder from starting another inference during teardown. After input closes, the worker allows two seconds for graceful exit before force-killing only a still-live owned PID tree, with bounded kill/exit waits and a generic failure if the child survives. The manager tracks closing workers per scope and awaits the previous close before native reads, forks or replacement creation. On successful async manager close, setup and worker shutdown finish before the journal closes.

A completed text-only receipt replays only when matching input carries the same stable `idempotency-key` or `client_metadata.turn_id`; conversation identity and identical text alone do not authorize completed replay. An old request's replay or expired-receipt refusal is handled before touching a newer active worker or consumer. Replay needs no worker or inference send and reports zero new usage. The manager retains at most 16 completed/interrupted payloads, expiring older payloads sooner when needed to fit the 16 MiB record bound. Older entries become expired refusal markers, and a new turn beyond the 4,096-receipt limit is refused. Pending calls and the active response are never discarded to make room. The journal itself has no lifecycle timer or deletion policy.

`src/adapters/claude-cli/session-native.ts` uses the public SDK `getSessionMessages` and `forkSession` helpers after the previous worker closes. A native checkpoint must match the source-history prefix, identify a completed assistant message, and have no unresolved tool calls. A clean record resumes its existing ID only when its entire recorded prefix matches and its checkpoint is the transcript's end. Edits and Undo fork through the latest matching safe checkpoint; forked message bodies and types must match the source prefix, and checkpoint UUIDs are remapped to the new transcript. Compacted or edited histories without a usable anchor, absent transcripts, missing metadata and identity/directory changes start a fresh native ID. Malformed transcripts or failed SDK reads/forks fail closed with a retryable error.

Dirty records and cold in-flight or tool tails never resume the unsafe old session. They fork from a prior matching completed checkpoint, or start fresh when no safe anchor exists. Before catch-up, supplied external results are matched and persisted, omitted saved results are restored beside their matching calls, and accepted instructions are recovered from the journal. These receipts and queues remain authoritative; a native transcript neither authorizes an external action nor replaces its actual result. Historical tool calls remain history and are not reissued. The implementation uses the existing query API and local native transcripts, without the alpha SessionStore or V2 session APIs; authentication and API routes retain their existing contracts.

`tests/providers/claude-cli-session-manager.test.ts`, `tests/providers/claude-cli-session-worker.test.ts`, `tests/providers/claude-cli-session-journal.test.ts`, `tests/providers/claude-cli-session-http.test.ts`, and `tests/server/claude-session-principal.test.ts` cover these boundaries with offline workers, real local HTTP streams and temporary storage. Active parser buffers retain the shared translator argument limits independently of HTTP lifetime; finished legs release parsed-request references. Resident conversations are bounded to 16.

## One-shot compatibility and stable projection

`src/adapters/claude-cli/stable-replay.ts` supplies a Claude-only replay builder to the shared `src/adapters/coding-agent/turn.ts` runner through its `conversationInput` slot; CodeBuddy keeps the default projection; Qoder opts into its image-omission markers through the same slot. It emits one legal user frame with an immutable text block per message, using identical formatting for a current message and its later history form. History is trimmed at whole-message checkpoints. Developer messages remain in the system prompt; the cut skips orphan historical results and retains a current result's originating call. Checkpoints are at most 20k characters apart; the cut can also discard the boundary message and any leading orphan tool-result blocks. The soft cap counts history characters, excluding the current input and truncation notice; retaining the current tool group's originating call can exceed it. Qoder CN image admission and Qoder-only omission markers follow the [coding-agent image contract](../providers/chat-compat.md#unmapped-modalities-are-recorded-not-dropped).

Canonicalization accepts only plain JSON, preserves arrays/literal values, and sorts object keys, including schema object keys and historical tool arguments. Instruction changes intentionally invalidate that prefix. Tools and schema object keys serialize deterministically, preserving catalog membership, MCP aliases, tool choice, and array order. Object-key sorting intentionally changes model-visible property order while preserving JSON values; integer-like keys follow JavaScript's numeric-key ordering. Invalid non-JSON history supplied by an internal caller fails at the runner's stdin projection as a 502, after launch, and the owned child is terminated. Ordinary HTTP JSON requests cannot carry cycles, accessors or undefined properties.

## One-shot tool capture

Without a conversation identity, a request that carries tools gets the shared capture-only MCP bridge (`src/adapters/codebuddy/tool-bridge.ts` and its server). `--tools ""` and `--strict-mcp-config` stay on, `--allowedTools` lists only the exact `mcp__opencodex__*` names of the selected catalog, and `tool_choice: none` advertises nothing. The runner returns the first assistant tool batch to the client and terminates the CLI at `message_stop`; the MCP handler never executes a call. Historical tool calls are replayed under the MCP names advertised in the current turn. With `acceptWireToolNames`, a tool_use that names an exact selected wire tool is accepted as that tool; the alias is output-only and never enters `--allowedTools`, and any other name ends the turn with `undeclared_tool_call`. This path uses `--no-session-persistence`, disabled setting sources, and a private per-turn `--system-prompt-file` instead of an inline prompt argument.

Claude Code controls actual cache breakpoints, so stable replay alone is not a measured savings claim. `tests/providers/claude-cli-efficiency.test.ts` checks replay stability against the legacy negative control, checkpoint behavior, catalog ordering and instruction authority; `tests/providers/claude-cli-tool-capture.test.ts` and `tests/providers/claude-cli-client-http.test.ts` cover capture ownership through the adapter and through real Responses and Chat Completions requests.

## Usage admission

Both paths record usage refusals through `onCliOutputError`: the persistent manager supplies accepted CLI error-result text, while the one-shot runner also supplies captured stderr on unsuccessful completion, after redaction. Local setup, spawn, stream, replay, and bridge-validation failures retain their client error semantics without recording a subscription reset. Login guidance is applied separately to the emitted client event.

`src/adapters/claude-cli/usage-admission.ts` gates `claude-cli` requests on the local Claude Code subscription quota. The adapter checks it before selecting either session path, and the Responses executor checks it before dispatch so an exhausted plan returns 429 `claude_subscription_cooldown` with `Retry-After` instead of a generic 502; Chat Completions keeps that code. Admission and cache invalidation share one window selection (plan windows plus custom windows in scope for the requested model family) and one `>= 100` threshold, so an expired window of another family never forces a re-read. A limit the CLI itself reports with a parseable reset ("resets 3pm (Zone)") is remembered until that time. The requested model id is caller input the CLI can reflect inside its own error wording, so a model id that itself carries the reset-clock phrase makes the message unattributable - real limit or echoed model - and the turn records nothing: the error still reaches the client and recorded or probed limits still gate, but a genuine limit seen only on such a turn is not newly cached.

A probe re-reads the account before it commits: an account switch mid-probe discards the answer (`unknown`, nothing persisted), and the newest refusal is merged at commit time with no await between that read and the write, so a CLI-reported reset is never overwritten. The file has one writer per `OPENCODEX_HOME`, the same single-owner topology as the spend ledger. The check reads the CLI's own sign-in in memory (`detectClaudeCodeTokenAsync`: Keychain without blocking the event loop, or `<CLAUDE_CONFIG_DIR>/.credentials.json`), caches the resolved identity for one minute, and sends the access token only to Anthropic's usage endpoint through `src/providers/claude-cli-usage.ts`, the same reader the account-pool quota probe uses. `CLAUDE_CONFIG_DIR` is passed to the child so the CLI and the check read one profile. The cache file `<OPENCODEX_HOME>/claude-usage-admission.json` stores only percentages, reset times and a hashed identity key. Every failure (no sign-in, malformed credential, unreachable endpoint) fails open as `unknown`, and a test process (`OCX_TEST_HOME_GUARD`) never resolves the real sign-in. If the executor's check throws or refuses, it releases the web-search sidecar's probe lease first; `tests/responses/responses-claude-preflight-lease.test.ts` and `tests/providers/claude-cli-usage-admission.test.ts` cover both.
